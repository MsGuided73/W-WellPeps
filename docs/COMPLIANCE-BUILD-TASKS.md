### W4 notes: security headers (done in code, deploy pending)

What the site now sends, in `wellpeps-site/nginx.conf.template` (the comments there explain each directive):

- **Content-Security-Policy**: pages may load scripts, styles, images and fonts only from wellpeps.com itself; no inline scripts, no `eval`; the only outside address they may call is the Supabase project (email signups and the future consent, privacy-request and analytics functions); nothing may frame the site; forms post only to the site. Style attributes (`style="..."`, a few chips on the hero and peptide cards) are the one inline allowance, because they cannot run code.
- **Strict-Transport-Security**: `max-age=31536000; includeSubDomains`, no `preload`. It applies to every subdomain, so each one (portal.wellpeps.com included) must serve valid HTTPS.
- **X-Content-Type-Options**, **Referrer-Policy**, **Permissions-Policy** (camera, microphone, location, payment, USB and the browser's ad-topics feature off) and **X-Frame-Options** (now `DENY`).
- **HTTP to HTTPS**: Coolify's proxy ends TLS, so nginx redirects (301) only when the proxy says the visitor used plain http (`X-Forwarded-Proto: http`). A request without the header, such as the health check, is served normally, so there is no redirect loop.
- To change the policy: edit the one `$wp_csp` line near the top of the template, then run `npm test` and `node scripts/security-headers-check.mjs`. A new outside address a page must call (a new function host, an analytics endpoint) has to be added to `connect-src` or the browser will block it.

How it was tested: no nginx or Docker is available on the dev machine, so the real nginx has **not** been run on this file. The header rules, redirect and password gate are read out of the template by a small emulator, the built site is served with exactly those headers, and Chromium walks every page and the interactive pieces (privacy panel, menu, assistant, eBook and checkout dialogs, signup forms, the locked-preview page) and fails on any policy violation. 65 unit tests cover the template itself.

Not verifiable yet, watch for these: (1) the eBook PDFs do not exist yet; when the first one is added, open it in Chrome from the dialog to confirm the built-in viewer works under `object-src 'none'` and `X-Frame-Options: DENY`. (2) Learning Center article HTML comes from Supabase at build time; an article that embeds an outside image, an iframe or a `<style>` block would be blocked in production, so open new articles after a deploy. (3) If the site is ever put behind Cloudflare, switch off its script-injecting features (Web Analytics, Rocket Loader) or the policy will block them.

Before or right after the deploy: run `nginx -t` in the built image if Docker is at hand, then check the live site with `curl -sI https://wellpeps.com/` (all six headers present) and, from a terminal inside the container (Coolify), `curl -sI -H "X-Forwarded-Proto: http" http://localhost/` (expect a 301 to https) and `curl -sI http://localhost/` (expect 200, so the health check keeps passing).
